# 候选项目验证

这里保留五份可独立运行、不需要历史源码基线的测试。不要把整个原验证目录搬入公开仓库。产品本身不需要 Node.js、Playwright 或服务器。

## 测试范围

| 文件 | 覆盖内容 | 限制 |
| --- | --- | --- |
| `save-mechanism.test.cjs` | 主动保存、未保存修改、加密/未加密备份往返、导入隔离、取消备份、最终确认保存、清空后保存等 14 组断言；同时覆盖部分快速开始、检查和过滤规则 | Node 中的模拟页面，不等同于浏览器完整端到端测试 |
| `first-open.test.cjs` | Edge、Chrome 各两个独立环境：初始四章为空、用户须知首次出现并记住确认、不自动创建存档、页面错误及 HTTP(S) 请求观测 | 只覆盖首次打开流程，不代表完整保存、打印、关系管理及备份流程已在浏览器验证 |
| `release-smoke.test.cjs` | 两种浏览器下新建、保存、刷新、未保存关闭、取消备份、联系人与多执行人、负责执行人、存档人称呼、两类备份跨环境恢复、三种打印文档内容及渲染 | 拦截原生 print 调用以检查生成文档，不操作系统打印窗口，不等于实体打印或人工 PDF 分页验收 |
| `type-switch.test.cjs` | 两种浏览器下四章 29 类非身份卡片切换、确认和取消、字段清空、管理设置保留、引用保护、保存恢复、两类备份往返 | 使用由当前模型生成的虚构样本；不等同于所有历史用户文件兼容验证 |
| `quick-item.test.cjs` | 两浏览器下首页第03项进入贵重物品、快速开始字段映射、空项跳过、重复检查，以及文件存放位置卡片的新增/编辑/保存/刷新和三种打印内容 | 仅使用虚构数据，拦截原生打印调用，不验证实体打印 |

测试中的姓名、账号、密码、地址样式和存档内容均用于虚构测试。它们不作为产品默认数据，也不是真实凭据。不要换成个人真实资料。保存机制测试使用内存模拟存储；浏览器测试使用独立临时上下文，不读取日常浏览器档案，也不生成截图或 `.life` 文件。

## 执行

在候选项目根目录，安装好 Node.js 后运行：

```sh
node --check app.js
node --check verification/save-mechanism.test.cjs
node --check verification/first-open.test.cjs
node verification/save-mechanism.test.cjs
```

浏览器测试另外需要本机已安装 Edge、Chrome 和 Playwright。可在开发环境安装：

```sh
npm install --no-save --package-lock=false playwright@1.62.1
node verification/first-open.test.cjs
node verification/release-smoke.test.cjs
node verification/type-switch.test.cjs
node verification/quick-item.test.cjs
```

安装开发依赖可能联网；离线产品不依赖它们。测试默认读取本目录上一级的 `index.html`，也可显式传入要验证的 HTML 路径。浏览器使用 `msedge` 和 `chrome` 通道；若缺少浏览器或通道不受当前系统支持，应记录未执行，不能写成通过。首次打开测试会拦截并记录 HTTP(S) 请求，不能把该局部观察当作所有交互都绝无联网行为的证明。

本轮实际使用 Node.js 24.18.0、Playwright 1.62.1、Windows 已安装的 Edge 和 Chrome；不代表软件最低版本要求。测试会自动启动浏览器的独立无头上下文。普通用户无需安装任何这些开发依赖。

## Release 候选包

`release-output/` 是忽略的独立本地输出目录，不提交到源码仓库。用户包只放三份程序文件、LICENSE、NOTICE、COPYRIGHT.md、三份 docs Markdown，以及由 `docs/download-readme.txt` 复制的 `00_第一次使用请看.txt`。

维护者重新打包时，按这份白名单复制到新的临时目录，保留 docs 相对路径，再压缩为 `人生存档_V1.0_非商业免费版.zip`；不要压缩整个项目目录。解压到独立位置，用三份浏览器脚本的入口参数测试该解压副本，并逐文件核对与源码一致。通过后才交作者审核，不自动上传或发布。

## 发布前仍需检查

- 在实际发布副本运行保存、未保存关闭、加密/未加密导入导出、错误密码及损坏文件流程。
- 验证联系人、第一/备用联系人、多执行人、负责执行人及删除引用保护。
- 验证已有卡片切换类型确认、清空和引用检查，存档人称呼及旧 `.life` 兼容。
- 人工核对三种打印、身份不重复、负责执行人标题及页眉页脚提醒，检查窄屏布局。
- 静态检查本地文件引用、网络调用、个人资料、绝对路径及秘密；新截图逐张审核。
- 核对已确认的 LICENSE、作者/年份和联系方式随发布材料正确提供；新增素材的分发权及隐私仍需审核，再决定发布。

这些是后续发布复核清单，不是本次已全部执行的结果。`.gitignore` 不是隐私扫描器；正式加入仓库前仍须人工审查待提交文件。

## 本次筛选与必要改动

保存机制测试直接复制，未修改断言。首次打开测试仅将旧电脑的 Playwright 绝对路径改为 `require('playwright')`、默认入口改为候选根目录，并调整结果标签；不再声称测试的是交付 ZIP。

第三阶段新增的两份浏览器回归脚本由现有验证脚本筛选适配：去掉原电脑路径、旧基线断言和截图输出，更新为当前打印提醒。备份只在独立浏览器临时下载和内存缓冲中处理，不将 .life 写到项目里；浏览器上下文关闭后释放。测试不会连接个人浏览器配置，也不修改应用源码。

两份新增测试及首次打开测试都支持把待测 `index.html` 路径作为第一个参数，可用于实际 ZIP 解压副本。请只使用测试副本。不要指向原正式版做写入性测试。

旧基线源码、历史快照、测试 `.life`、测试记录、截图、PDF 构建脚本及依赖这些文件的测试均不复制。其他旧测试暂不移植，不代表其覆盖的产品功能被删除。
